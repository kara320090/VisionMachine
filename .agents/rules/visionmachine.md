# VisionMachine 프로젝트 작업 기준

먼저 README.md, docs/PROJECT_SCOPE.md, docs/STATUS.md와 작업 파트 문서를 읽는다. 사용자 최신 합의와 실제 저장소 상태를 우선한다. 이 문서는 기술 선택안과 데이터 계약 초안을 포함하며 학교 양식 자체가 아니다.

- 한 저장소에 apps/android, server, data-pipeline, ml, firmware, contracts를 유지한다. API·센서·모델 입출력은 packages/contracts/src/vm_contracts/models.py가 원본이며 JSON Schema를 재생성한다.
- 사진은 기존 휴대폰 카메라로 찍는다. 한 대의 UNO R4 Minima가 완성 모듈 센서만 수집하며 USB-C로 휴대폰에 보낸다. 인터넷 전송은 휴대폰이 담당한다.
- 앱은 첫 주부터 구현한다. 서버·센서·모델이 준비될 때까지 기다리지 않는다. 모의 자료는 명시하고 실측·학습·최종평가와 분리한다.
- 원본/보정값·측정시각·장치/펌웨어·교정 버전을 기록한다. 결측을 0으로 대체하지 않는다. 토양 원시값을 보정 없이 절대 수분함량 %로 표시하지 않는다.
- 사진·센서는 동일 검사 ID·대상 ID로 연결한다. 서로 다른 공개자료에서 임의 짝을 만들지 않는다. 개체·과실·구매/수확 묶음·중복 사진을 train/val/test 사이에 섞지 않는다.
- 모델 미탑재 시 pending_model. 모델 없는 상태에서 정상·진단 신뢰도·원인·성능을 만들어내지 않는다. 테스트 응답은 mock임을 UI와 응답에 표시한다.
- 8종은 후보/기록 범위이며 8종 성능 검증 완료가 아니다. 실제 표본 수·라벨·정확도·교정계수·시작일·추가 자원을 창작하지 않는다.
- 광학 확장은 예비시험·참고 정답·반복성 확인이 필요하다. 지원금 증액을 성능 보장으로 해석하지 않는다. 납땜·회로 제작·IR 필터 제거를 기본 요구로 추가하지 않는다.
- GitHub는 공개 저장소다. .env, 키, 토큰, 서명키, 원본 사진, 실제 시험 정답, 실 DB, APK/AAB, 모델 가중치, 학교 개인정보 서류를 커밋하지 않는다. public fixture는 합성이라고 표시한다.
- 기존 파일·사용자 변경을 먼저 확인한다. 요청 범위의 작업을 진행하며 기존 데이터 삭제·force push·실제 결제·외부 배포·계정 설정 변경은 별도 요청 없이 수행하지 않는다.
- 사용자는 검증된 작업 단위마다 commit과 origin push를 바로 수행하도록 요청했다. 관련 파일만 stage하고 현재 작업 branch를 push한다. force push·타인의 변경 덮어쓰기·자동 배포는 하지 않는다.
- 코드 변경과 함께 관련 테스트·실행방법·STATUS를 갱신한다. 실행하지 않은 테스트나 기기 시험을 통과했다고 쓰지 않는다. 커밋에는 검증된 한 작업 단위를 담는다.
