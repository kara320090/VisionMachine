## 2026-11-14 Android–4090 서버 연결 개발

- 기존 RGB 화면에 런타임 서버 주소·기기용 키 설정과 Keystore 암호화 저장을 추가했다. 원본 사진과 사진 ID·작물·해시가 일치하는 USB 패킷/센서 평가 스냅샷을 인증한 `/api/v1/inspections`로 전송하고 기존 결과/이력/CSV에 연결한다. 최대 8장 순차 처리와 개별 실패 후 계속 처리하며, 서버 API는 한 요청의 1~8장도 지원한다.
- 서버는 모델 카드 해시·입출력을 검사하고 CUDA 공급자가 없으면 미준비로 처리한다. EXIF/RGB/BICUBIC 256/중앙 224/ImageNet/NCHW 전처리는 기존 Android의 5개 픽셀 골든과 일치했다. 원본 파일·센서값을 저장하고 같은 검사 재시도/충돌을 처리한다. `SensorScoring.kt`/`CompositeIndex.kt`의 점수식과 결측·포화·mock 보류 규칙은 수정하지 않았다.
- Ubuntu의 ORT 1.23.2 / CUDA runtime 12.9 / cuDNN 9에서 기존 C_seed42 체크포인트를 변환해 **앱 모델 카드와 바이트 SHA-256이 동일한 ONNX**를 복원했다. 추가 학습·가중치·모델 카드 변경 없이 실제 CUDA 세션과 GPU 노드 실행을 확인했다. 합성 RGB 입력 8개에서 원본 PyTorch와 CUDA ONNX의 최대 출력 차이는 0.000003934였다.
- Python 검사 89건, 계약/OpenAPI/기존 HTTP smoke 통과. Android debug APK/계측 APK·JVM 4건·lint 통과(오류 0/경고 25/힌트 2). API 36 에뮬레이터 계측 36건 중 30건 통과·6건은 비공개 사진/실보드 자료 부재로 skip했다. 실제 Ubuntu 서버에 8장과 합성임을 표시한 센서 스냅샷을 전송해 8장 완료·결과 이력·서버 GPU 표시를 확인했다. 실제 GPU의 8장 단일 multipart 요청 201·재시도 200·조회 200·내용 충돌 409도 확인했다. 합성 실행/연결 검사이며 재배환경 정확도를 새로 평가한 결과는 아니다.
- 공개 배포용 사용자 로그인/기기별 키 폐기·HTTPS 서버·실휴대폰/Tailscale 검증은 남아 있다. 현재 내부 서버 키는 APK에 고정하지 않는다. 실행·계약·검증 구분은 [SERVER_GPU](SERVER_GPU.md)를 따른다.

## 2026-11-13 아두이노 센서 4종 인계 — 현재 업로드 v0.2.0

- 사용자 요청에 따라 아두이노 쪽만 진행했다. Android 앱 소스 수정·앱 빌드 산출물 배포·Play 작업은 수행하지 않았다. UNO R4의 SEN0308 A0 ADC·SEN0334 온습도에 SEN0364 광학·SEN0206 표면온도 읽기를 추가했다. 같은 조립·배선에서 PC USB 확장 응답을 받았다.
- 기존 3필드 요청과 `basic`은 확장 키 없는 기존 응답을 유지한다. 명시적인 `sensor_profile=extended` 요청에만 버전이 있는 `extensions`를 추가한다. Python 원본 계약·요청/응답 JSON Schema·OpenAPI를 갱신했고, 확장 없는 모델의 직렬화에도 임의 `extensions:null` 키를 넣지 않는다.
- 광학은 SMUX 설정 쓰기·읽기 대조, 준비 대기 상한, 검사한 데이터 블록 읽기로 순차 노출 2회의 원시값 12개를 보낸다. gain 16×·ATIME 29·ASTEP 599·노출당 50.04ms·주변광/LED off·포화 상태를 기록한다. 매 요청 설정값을 확인하고 초기화·읽기 실패 후 재설정한다. 라이브러리의 무한 대기/오류를 버리는 캐시 읽기는 사용하지 않는다.
- MLX90614는 대상·센서 자체 온도 레지스터와 방사율 EEPROM을 읽고 SMBus PEC CRC-8·오류 비트를 검사한다. 실패는 `null`·오류이며 다른 정상 센서의 값을 지우지 않는다. EEPROM 쓰기나 임의 교정값 추가는 하지 않았다.
- 최종 빌드·업로드 성공: flash 69,312 bytes, 전역 RAM 6,100 bytes. Arduino CLI 1.6.0, Renesas UNO core 1.6.0, SHT31 2.2.2, BusIO 1.17.4, AS7341 1.4.1. core 내부 경고가 있으며 이 스케치의 빌드를 막지 않았다.
- 최종 보드의 실제 USB 패킷 16개(확장 실측 5·기본 1·기존 USB 회귀 10)를 원본 계약으로 검증했다. 확장 5회는 광학·표면온도와 기본값을 받고 오류가 없었으며 최대 프레임 1,018 bytes였다. 잘못된 요청은 계측값을 모두 `null`로 반환하고 초과 줄·분할 수신에서 복구했다.
- 별도의 임시 진단 빌드에서 확장 센서를 실제 응답 없는 주소 0x38·0x59로 지정한 오류 시험 3회(extended/basic/extended)를 수행했다. 확장 요청 2회는 두 센서만 `null`·오류이고 SHT31 값은 유지됐으며 기본 요청은 기존 형식이었다. 이는 물리적인 센서 분리·재연결 시험이 아니다. 시험 뒤 정상 주소를 쓰는 진단 출력 없는 v0.2.0을 복원했다.
- `scripts/check.py`의 pytest 82건·계약·OpenAPI·manifest·HTTP 점검, MSVC의 요청 디코더 검사 282개·공식 Melexis 예제 기반 PEC/온도 검사 5개가 통과했다. 실제 로그·장치 식별자는 공개 Git 밖에 보관한다.
