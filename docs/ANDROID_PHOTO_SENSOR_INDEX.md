# Android 0.4.0 촬영·8장 일괄 분석·센서/종합 지수

사용자 요청으로 첫 화면에 바로 촬영과 사진 추가를 배치하고, 최대 8장 목록·사진별 작물/상태/결과를 표시한다. 한 번의 ‘선택 N장 모두 분석’으로 기기 내 RGB 모델을 사진별 순서대로 실행한다. ONNX 입력 배치를 8로 바꾸거나 병렬 처리·새 모델 학습을 수행한 것이 아니다. 기존 모델 가중치·전처리·이력·카메라 원본·USB 펌웨어는 유지한다.

## 사용 흐름

1. 새 사진의 작물을 고른 뒤 **바로 촬영** 또는 **사진 추가**를 누른다. 사진 선택기는 여러 장을 고를 수 있고, 추가 선택도 기존 목록에 이어 붙인다. 중복 URI는 한 번, 최대 8장만 받으며 초과 수를 안내한다. **파일에서 여러 장 추가** 경로도 제공한다. 파일 선택기는 보통 한 장을 길게 누른 뒤 다른 사진을 눌러 여러 장을 선택한다. 시스템 선택기 문제가 있어도 다른 경로를 사용할 수 있다.
2. 촬영은 기존 카메라 앱의 `TakePicture` 결과를 원본 FileProvider URI에 저장한다. 취소하면 기존 선택 사진을 유지한다. 선택 입력인 개체/묶음 ID는 비워 두면 `unassigned`다. 이것은 실제 개체가 서로 독립적이라는 선언이 아니다. 중단된 촬영은 원래 pending URI로 복구한다.
3. **선택 N장 모두 분석**을 누른다. 사진별 작물을 바꿀 수 있고, 각 사진의 대기/분석 중/완료/실패를 표시한다. 한 장의 읽기·메모리 오류가 다른 사진을 중단하지 않는다. **사진·결과 보기**로 해당 사진과 결과를 미리 본다.
4. 각 사진의 **이 사진에 센서 측정**으로 USB 화면을 연다. 그 실제 대상에 센서를 사용해 측정한다. 사진 참조 ID·작물·사진 파일 SHA-256이 모두 일치하는 실측만 사진 결과에 연결한다. 다른 대상의 ‘최근 센서값’을 붙이지 않는다.
5. USB 화면의 **작물별 센서 기준 설정**에서 조건·출처·하한/상한·허용편차를 입력하고 적용한다. 적용 전이나 기준이 없을 때 점수를 만들지 않는다. 설정 뒤 새로 측정해야 새 기준을 사용한다.
6. 사진 화면으로 돌아오면 동일 사진의 최신 실측 평가가 연결된다. RGB 원출력, 센서 기준 이탈 점수, 사용자 가중 종합 지수를 함께 확인하고 CSV로 내보낸다. 과거 평가에는 사용 당시 기준·버전·가중치가 남는다.

갤러리 사진은 실제 노출 시각·개체·구매 묶음을 추정하지 않는다. 사진 참조 전용 저장소에 URI와 새 참조 ID를 기록하며, 촬영시각은 빈 값/미상이다. 실측 수신 시각과 사진 노출 시각을 혼동하지 않는다. 사진 선택기의 장기 URI 권한을 요청하지만, 사용자가 원본을 삭제하거나 접근을 해제하면 사진을 열 수 없을 수 있다.

## 센서 점수의 정의

4개 모듈의 5개 관측 항목을 지원한다.

| 모듈 | 점수에 사용할 값 | 필수 기준/품질 조건 |
|---|---|---|
| SHT31 | 외기 °C, 상대습도 % | 해당 작물·생육단계·주야간의 명시한 범위, 유효 측정 |
| SEN0308 | 토양 원시 ADC | 같은 흙·삽입 조건의 사용자 기준과 같은 ADC bits. 수분 %로 변환하지 않음 |
| AS7341 | F1~F8 원시 채널 합 | 게인·ATIME·ASTEP·광원/LED·채널 순서가 기준과 같음, 포화·읽기 오류 없음 |
| MLX90614 + SHT31 | 표면온도−외기온도 차 °C | 대상·측정거리·시야/환경을 명시한 사용자 범위와 유효한 두 온도 |

범위 `[L,U]`, 사용자 허용편차 `t`, 관측 `x`에 대해:

```text
d = max(L-x, x-U, 0)
e = max(d-t, 0)
항목 점수 = clamp(100 × e / (U-L), 0, 100)
센서 이탈 점수 = 설정된 모든 항목 점수의 산술평균
```

범위 안은 0점이며 범위에서 멀수록 높은 점수다. `t`는 사용자가 선택한 여유 범위이며 실측한 센서 정확도·교정계수나 제조사 최대 오차를 추정한 값이 아니다. 범위 폭으로 거리를 정규화하는 앱 규칙 v1이며, 병해 라벨로 검증한 손실/확률 모델이 아니다.

설정한 항목 중 하나라도 결측·오류·포화·조건 불일치이면 전체 센서 점수와 종합 지수를 산정하지 않고 개별 유효 점수만 보여준다. 기준을 정하지 않은 항목은 0점으로 대체하지 않는다. 전체 5항목 중 설정/산정한 개수를 표시하므로 온도 한 항목 점수가 센서 4종 전체 판정으로 보이지 않게 한다. mock은 실측 점수에서 제외한다.

## 참고 범위와 사용자 적용

참고 입력값은 자동 활성화하지 않는다. 다음 공개 문헌의 특정 조건에서 제시한 주간 온도만 편집창에 준비하고 사용자가 현재 조건을 확인한 뒤 적용한다.

- [NMSU Circular 556](https://pubs.nmsu.edu/_circulars/CR556/index.html): 토마토는 초기 저온 처리 뒤 육묘 주간 70–75°F, 온실 오이는 주간 80–85°F, 온실 상추는 주간 60–65°F. °C는 `(°F−32)×5/9`로 변환한다. 모든 생육단계·야간의 최적 온도로 확대하지 않는다.
- [UConn/UMass 허브 모종 재배 안내](https://ipm.cahnr.uconn.edu/herbs-greenhouse/): 허브 모종에 공통으로 제시한 주간 70–75°F를 바질·로즈마리의 편집용 참고로 제공한다. 품종별 검증값으로 표시하지 않는다.
- 고추·청경채·케일·가지의 수치 및 습도·토양·광학·표면−외기 온도차 범위는 이 작업에서 검증한 근거가 없어 비워 둔다. 사용자가 조건·출처 또는 실제 기준 측정 기록과 함께 정한다. 토양/광학은 새 기준을 입력할 때 실제 패킷의 ADC/광학 조건을 함께 저장한다.

점수가 낮아도 병해가 없다는 의미가 아니다. 이 지수는 센서·조건별 기준과 관측의 거리를 보이며 병명·식용 안전·당도·광합성 유효광을 추정하지 않는다.

## 사진 AI와 합산한 종합 지수

```text
종합 지수 = (RGB abnormal 출력 × 100) × (1-w) + 센서 이탈 점수 × w
```

초기 `w=0.5`는 화면에 표시하는 사용자 설정 기본값이다. 사용자가 슬라이더로 바꾸며, 학습이나 비교 실험으로 추정한 최적 가중치가 아니다. 지수 0~100은 병해 확률·정확도나 학습된 멀티모달 융합 모델의 성능이 아니다. RGB 모델 원출력과 센서 근거를 분리해 표시하고 종합 지수에 별도의 정상/이상 임곗값을 만들지 않는다. 유효 센서 점수가 없으면 종합 지수도 없다. 사용된 센서 항목 수·가중치·식·참조/측정 ID를 이력과 CSV에 보존한다.

사진 AI의 실제 학습 범위는 모델 카드의 8종이다. 화면에는 이 범위의 `tomato`·`kale`과 기존 기록 범위의 `cherry_tomato`·`eggplant`도 구분한다. 방울토마토에는 일반 토마토 자료를 참고한다는 표기를 사용한다. 가지는 센서 기록 대상으로 유지하며 RGB 분석을 보류한다. 기존 서버 계약의 작물 목록은 이 로컬 화면 변경으로 확대하지 않았다. 실제 센서·RGB 짝자료를 학습한 새 융합 모델은 추가하지 않았다.

## 저장·시험·빌드

- `PhotoReferenceStore`: 갤러리/촬영 사진 참조와 작물. 기존 `captures_v1`을 덮어쓰지 않는다.
- `SensorProfileStore`, `SensorScoring`: 사용자 기준·출처·적용 버전과 기준 거리 계산.
- `SensorStore`: 기존 원본 패킷·오류에 사진 해시와 평가 스냅샷을 추가한다. 기존 기록의 새 필드는 null로 읽는다.
- `RgbHistory`: 기존 7필드를 보존하며 작물·사진/센서 ID·센서 평가·종합 지수 JSON 필드를 추가한다. 기존 기록에는 없는 값을 생성하지 않는다.
- `ReferenceIndexTest`: 범위/허용편차·가중식·비정상 수치 회귀시험.
- `SensorAssessmentTest`: 명시적인 합성 패킷으로 모듈별 단위·결측/포화/노출 불일치/mock·저장·출처·합산 검사를 수행한다.
- `RgbWorkflowTest`: 비공개 보관 사진 8개 실제 모델 실행·추가 선택·개별 결과·중간 실패 지속, 합성 JPEG로 카메라 파일 결과 처리, 사진 해시 불일치 거부·올바른 측정 연결을 검사한다. 실제 휴대폰 외부 카메라/USB 왕복과 구분한다.

패키지는 `org.visionmachine.agriclinic`, 버전 `0.4.0(versionCode 4)`다. 기존 업로드 키와 모델을 사용해 AAB를 만든다. 실제 Play 업로드·활성 여부는 [PLAY_INTERNAL_TEST](PLAY_INTERNAL_TEST.md)에 따로 기록한다. 빌드는 `apps/android/gradlew`의 assemble/lint/test 명령을 사용한다.
